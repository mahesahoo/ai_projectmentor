# AI Academic Project Mentor

An agentic platform that turns a student's rough project idea into a full academic
project blueprint — feasibility, scope, tech stack, timeline, and risks — then keeps
mentoring through execution via chat, progress-driven replanning, and on-demand
documentation. Milestones 1–3 complete (see status sections below).

## Stack
- **Backend:** FastAPI (Python)
- **Frontend:** plain HTML/CSS/vanilla JS (no build step)
- **Database:** SQLAlchemy ORM → SQLite by default, PostgreSQL-ready
- **Auth:** JWT (24-hour expiry)

## Setup

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Run

```bash
uvicorn app.main:app --reload
```

Open **http://localhost:8000** — this serves both the frontend pages and the API
from the same process (no CORS issues, no separate frontend server).

- `/` → landing page
- `/register.html` → create account
- `/login.html` → log in
- `/profile.html` → view/edit profile, log out
- `/skill_assessment.html` → rate proficiency per tech stack
- `/docs` → interactive API docs (Swagger UI, auto-generated by FastAPI)

## Agent pipeline setup (Milestone 2 + 3)

Every agent — Feasibility, Scope, Tech, Timeline, Risk (the blueprint pipeline),
plus the conversational Mentor, Replan, and Documentation agents (Milestone 3) —
calls the Gemini API (`gemini-3.5-flash`, on Gemini's free tier) and needs a key
set before running the app. Get a free key at https://aistudio.google.com/apikey,
then:

```bash
export GEMINI_API_KEY="..."
uvicorn app.main:app --reload
```

Never commit the key — it's read from the environment only, same convention as
`DATABASE_URL` below. The app boots fine without this set (Milestone 1 routes
don't need it); only idea submission's background pipeline (and the M3 chat/
replan/document endpoints) need the key, and fail gracefully (pipeline sets
`idea.status` -> `"failed"`; the M3 endpoints return an error response) if it's
missing.

## Switching to PostgreSQL

No code changes needed. Just set an environment variable before running:

```bash
export DATABASE_URL="postgresql://user:password@localhost:5432/project_mentor"
pip install psycopg2-binary   # Postgres driver, not needed for SQLite
uvicorn app.main:app --reload
```

## API endpoints

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/api/auth/register` | No | Create a student account |

## Milestone 2 status

All five tasks complete:
- Task 1 — Feasibility Analysis Agent (`app/agents/feasibility.py`)
- Task 2 — Scope Definition Agent (`app/agents/scope.py`)
- Task 3 — Technology Recommendation Agent (`app/agents/tech.py`) — the one
  agent that actually consumes Milestone 1's `SkillAssessment` data, weighting
  stack choices toward technologies the student already knows
- Task 4 — Timeline Planning Agent (`app/agents/timeline.py`)
- Task 5 — Validation, run against 4 varied sample ideas (solid, vague,
  overambitious, and a skill-weighting check) via the real Gemini API

Pipeline: `app/agents/pipeline.py::run_pipeline` chains the four agents,
persisting each stage's output and advancing `idea.status` through
`analyzing_feasibility -> analyzing_scope -> analyzing_tech ->
analyzing_timeline -> analyzed`. A `"not_feasible"` verdict stops the
pipeline right after the Feasibility stage rather than forcing the later
agents to scope/plan a project the student never actually proposed. Any
failure (Gemini API error, missing key, etc.) sets `status = "failed"`.
Fetch the aggregated result via `GET /api/ideas/{id}/blueprint`.

## Milestone 3 status

All four tasks complete:
- Task 1 — Risk Assessment and Mitigation Agent (`app/agents/risk.py`) — the
  5th and final stage of the blueprint pipeline (`analyzing_timeline ->
  analyzing_risk -> analyzed`), reads the full scope/tech/timeline and flags
  concrete, project-specific risks with likelihood + mitigation.
- Task 2 — Conversational Mentor (`app/agents/mentor.py`,
  `GET/POST /api/ideas/{id}/chat`) — plain-text, multi-turn chat grounded in
  the finished blueprint, using Gemini's native chat `Content`/`Part` format
  for real conversation memory. Synchronous (immediate reply), not a
  background task like the pipeline. Gated on `status == "analyzed"`.
- Task 3 — Progress tracking + replan (`ProgressUpdate` model,
  `app/agents/replan.py`, `GET/POST /api/ideas/{id}/progress`,
  `POST /api/ideas/{id}/replan`) — logging progress is a free DB write;
  replanning (re-running Timeline + Risk with the progress history as
  context) is a separate, explicit, costly action so a chatty student can't
  accidentally trigger repeated agent runs. New `TimelinePlan`/
  `RiskAssessment` rows are added, not overwritten — old plans stay in the
  DB as an audit trail.
- Task 4 — On-demand documentation generation (`app/agents/docs.py`,
  `GET/POST /api/ideas/{id}/documents`) — synopsis, methodology, and
  progress-report generation as persisted Markdown, generated only when
  requested (never automatically), each persisted as a new row.

**Design decision:** the brief describes progress updates as triggering plan
adjustments "via the agent pipeline." This build keeps logging progress and
triggering a replan as two separate actions rather than auto-replanning on
every log entry, to keep API cost predictable — a deliberate, documented
deviation from the brief's literal wording (see `infos/MILESTONE3_CHECKLIST.md`).

**Validated end-to-end** (`infos/MILESTONE3_CHECKLIST.md` task 21): a full
continuous walkthrough on one idea — pipeline through all 5 agents, 2-turn
chat with confirmed memory and grounding, 2 progress logs followed by a
replan (confirmed the timeline actually changed and old/new rows both
persisted), and all 3 document types (confirmed the progress report refuses
to fabricate progress that wasn't logged) — plus an edge-case run on a
deliberately vague/infeasible idea confirming chat and document generation
degrade gracefully with no scope/tech/timeline/risk, while `replan` correctly
returns `409` since there's nothing to replan. 37/38 automated checks passed
(the one failure was a wrong URL in the test script itself, not an app bug).
